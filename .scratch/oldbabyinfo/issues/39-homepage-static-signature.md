## Comments

**構圖：** 首屏是 `StadiumSignature` 全滿版背景（寬度 `min(150vw, 1500px)`，刻意左右出血），
競技場線稿降到 0.5 透明度作為氛圍，文字與 CTA 疊在純色 `--surface-950` 上（不是漸層，避開
ADR-0008 記錄的中段禁字區）。刻意不用「左文右圖」的預設 split-hero 版型——那正是規範明文
警告的樣板。標題「查得到，也要查得準」單行完整、無多行堆疊，副標與單一 CTA 靠版面左下角，
不置中、不對稱堆疊。

**首頁重用既有系統，沒有發明新視覺語言：** 攻擊／持久零件標示直接用票 13 的
`PlaystyleSymbol`（裸符號，無色塊容器），competition 場地圖用票 07 的 `StadiumSignature`，
顯示字體與色階全部沿用既有 tokens。全站只有一套視覺語言（ADR-0006）。

**真實資料，非佔位內容：** 兩個零件亮點直接用既有的 `filterByType` + `sortParts`（不寫新邏輯，
重用票 12 已測試過的排序）算出「目前最高攻擊」＝蒼龍爆刃（attack 75）、「目前最高持久」＝
Yield（stamina 65）；賽事區塊用既有的 `splitByDate` 取最近一場真實賽事（2026-07-26
14:00・桃園環球A19・G3・32人・線上報名，來源連到真實 Google Sheet）；統計列的 168／431
是即時算出的真實筆數，不是寫死的數字。

**導覽列：** 新建 `SiteHeader`（`src/components/site-header.tsx`），一個有自身色邊界（self-colored
1px hairline，16% 透明度）的容器列，非預設靠邊連結——目前僅用在首頁，尚未接進共用 layout
（超出本票範圍，未來若要站內統一導覽是另一個獨立決定）。

**頁尾：** 連結列與語言切換器置中同列（不是甩到兩端），資料來源改用純文字連到五個真實來源
（不捏造 logo），巨大品牌字「OldBabyInfo」貼齊頁尾最底部、無多餘留白，符合規範「置頂於背景
層、緊貼底部但不裁切內容」的正確做法——過程中發現並修掉一次真的裁切事故（見下）。

**過程中發現並修正的三個真問題（不是靠 checklist 硬套，是實測抓出來的）：**

1. **CTA 違反本專案自己在 `colors.css` 寫的規則。** 第一版把 CTA 按鈕整個填滿
   `--accent-on-dark`，但 `colors.css` 的註解明寫「強調色…節制使用（邊框、連結、狀態），
   絕不作為大面積填色」。截圖回看時才發現自己直接違反了專案既有的色彩系統決策，改成
   透明底、accent 邊框＋文字的樣式，hover 用 12% 低透明度色調鋪底，不是實色互換。
2. **頁尾巨字被頁面底部硬生生切掉一角。** 第一版「Baby」的 `y` 下伸筆畫被裁在文件最底端，
   截圖裁切驗證後才看到——這正是規範說的「意外裁切」而非「刻意出血」，因為裁切邊是文件
   終點本身，不是有設計意圖的畫框。加了 `padding-bottom: 0.22em` 讓下伸部位完整露出。
3. **手機版導覽連結斷字直排。** 手機寬度下「零件庫」「賽事行事曆」因為 flex 子項被壓縮到
   逐字換行、直排顯示，明顯是 bug 不是設計。改為 `flex-wrap` + 連結 `white-space: nowrap`，
   窄螢幕下導覽自動換行到第二列並置中；同時頁尾巨字的 `clamp()` 下限也太大，在 390px
   寬度下右側被裁掉一個字母，調整 vw 係數與加上左右 padding 後在手機寬度下完整顯示。

三個問題都是先用 Playwright 截圖（桌面、英文版、手機 390px 寬）逐一目視核對後才發現的——
`typecheck`／`lint`／`vitest`／`build` 全程保持全綠，完全不會抓到這幾類問題，這也是整個
專案這幾週下來一直驗證到的同一個教訓。

**Pipeline：** `npm run typecheck`、`npm run lint`、`npx vitest run`（116/116）、
`npm run build` 全數通過；並用 `next start` 起正式伺服器逐一截圖驗證 zh-TW／en 桌面版
（1440×900，首屏無下一段落露出）、手機版（390×844，導覽與頁尾巨字皆修正後正常）、
零件亮點卡片的符號與數字精確垂直置中。
