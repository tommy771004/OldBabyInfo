# 05 — 色彩系統與連續色溫過渡

**What to build:** 一套色彩 token，能同時表達「場上」的深色高能與「場邊」的溫暖易讀，且兩端之間的過渡是連續的，任何段落交界都不出現硬色邊。

**Blocked by:** 02

**Status:** ready-for-agent — done, see Comments

落實 ADR-0006。

- [x] 定義單一調色盤，深場地端與暖閱讀端是同一系統的兩端而非兩組配色
- [x] 暖端色彩由場地色系推導，明確不使用米白、燕麥或通用編輯風背景
- [x] 提供一個示範頁面，從深端捲動至暖端，目視確認沒有任何硬色邊（用 Playwright 實際截圖驗證，不是肉眼掃過）
- [x] 所有文字與其背景的對比度通過 WCAG AA（含強調色的深淺兩個變體）
- [x] token 以 CSS 變數實作，深暖兩端可被任何元件取用

## Comments

### 方向

Beyblade X 官方品牌是紅黑識別，不是常見的藍紫；核心物理現象是摩擦生熱。色階選了暖褐 → 赤鏽 → 暖陶土白這條路線，刻意避開兩個 anti-slop 法明確點名的預設：冷藍炭黑（深色版預設）與米白／燕麥（淺色版預設）。11 階連續色階，見 `src/styles/colors.css`，設計推導與角色定義見 [ADR-0008](../../../docs/adr/0008-surface-gradient-color-system.md)。

### 過程中發現一個真正的問題，不是規格要求但必須解決

原始版本的示範頁把文字平均分布在整條漸層上，肉眼看起來漸層本身是連續的（沒有硬色邊），但**沒有意識到「連續漸層」不等於「疊在漸層上的文字到處都能讀」**。用 Playwright 截圖後放大檢查，並實際算出文字所在位置的內插背景色（不是查最近的命名色階），才發現色階中段（約 50%–60%）是中等亮度，深墨淺墨在那個範圍都掉到 WCAG AA 以下，最低到對比度 1.03（幾乎不可讀）。

修法不是調色（中等亮度背景本來就是黑字白字的物理天花板），是重新排版：深色墨安全區落在色階 0%–45%，淺色墨安全區落在 62%–100%，中間留一段刻意的無文字過渡帶。這個限制寫進 ADR-0008，並在 07、41 號票留了指標——任何未來要疊內容在這個漸層上的頁面都要遵守，不能只看 build 綠燈就當作視覺沒問題（這類 bug 是量測層級的，typecheck 完全抓不到）。

### 工具

這個過程中裝了 Playwright（`scripts/screenshot.mjs`，通用化成吃路徑參數）作為視覺驗證手段——Chrome 擴充功能在這個環境沒有連線，這是替代方案，06、07、08 號票的視覺工作可以沿用。
