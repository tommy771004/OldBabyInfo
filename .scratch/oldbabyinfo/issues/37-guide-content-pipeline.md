# 37 — 新手指南內容管線與版式

**What to build:** 一套長文內容的呈現方式，讓新手指南讀起來舒服，且日後新增文章不必再處理版式。

**Blocked by:** 08

**Status:** done

內容頁位於 ADR-0006 所稱「場邊」，採暖端色溫與最低動效強度。

- [x] 內容以 Markdown 或 MDX 撰寫，新增文章不需改動程式
- [x] 內文版式定案：行長、行高、標題層級、圖說、引言
- [x] 引言與資料來源註記使用芫荽，其餘為台北黑體
- [x] 具備目錄與段落錨點，長文可跳轉
- [x] 中文標點與換行處理正確，無孤字與不當斷行

## Comments

**技術選型：純 Markdown 語意，用 MDX 的編譯管線但不用它的 JSX 能力。** 新增
`next-mdx-remote`（RSC 版）、`gray-matter`、`rehype-slug`、`remark-gfm`、`github-slugger`
五個依賴。文章內容目前只需要標題、段落、清單、引言、圖片這些純散文元素，不需要在內容裡嵌入
互動元件，所以刻意不引入完整的自訂 MDX component 系統——保留 MDX 編譯管線只是因為它能在
RSC 情境下乾淨運作、且必要時（例如未來想在文章裡嵌一個真實的零件卡片元件）可以直接升級，
不用整套重寫。

**「場邊」色溫：不需要額外覆寫。** 票面要求內容頁採暖端色溫，但票 41 已經把全站預設色溫換成
暖端（`surface-100`／`ink-on-light`），指南頁面完全不需要任何局部樣式覆寫就自動落在正確的
色溫——這是 41 號票的自然延伸，不是這張票要重新決定的事。

**行長／行高／標題層級／圖說／引言的具體數字：** 內文容器 `max-width: 38em`（比一般西文排版
建議的 65-75 字元窄，因為中文字符本身較寬較密，同樣視覺行寬換算成中文字數會偏短，刻意調窄）、
`line-height: 1.9`（同樣理由，比西文常見的 1.5 更寬鬆）。標題沿用既有全站字體映射
（`fonts.css` 已經把 h1-h3 對應到 Combat 顯示字體，這裡不用重新宣告）。圖說與引言／資料
來源註記共用同一條規則：`font-family: var(--font-accent)`（芫荽）——票面把「引言」跟
「資料來源註記」放在同一句要求裡，代表兩者本來就該用同一套處理，於是在
`content/guides/README.md` 明訂內容撰寫慣例：兩者都用 Markdown 的 `>` 引言語法撰寫，
CSS 只需要一條 `blockquote` 規則就能同時覆蓋，不需要為「資料來源」另外發明一套語法。

**目錄與錨點：真的可以跳轉，不是只有正確的 `href`。** 目錄清單獨立於 MDX 渲染之外，用
`extractHeadings()`（純函式，見測試）從原始 Markdown 文字掃出標題清單，並用
`github-slugger`——跟 `rehype-slug` 內部用的是**同一個套件**——產生 slug，確保目錄連結
算出來的 `#slug` 一定跟渲染後標題實際被賦予的 `id` 完全一致，不會有兩套獨立算 slug
邏輯各自飄移導致連結失靈的風險。用 Playwright 實際點擊目錄連結，量測點擊後 `scrollY`
真的改變、且目標標題確實進入可視範圍，不是只檢查 `href` 字串長得對。

**中文排版：靠瀏覽器原生換行規則，不是自己刻一套。** 全站 `<html lang={locale}>` 本來就
正確設定（票 06 已完成），現代瀏覽器會依 `lang` 屬性自動套用正確的中文避頭尾標點規則，不需要
額外處理。唯一主動加的是 `text-wrap: pretty`（段落）與 `text-wrap: balance`（標題）——
現代 CSS 原生的孤字防止屬性，不是手動塞 `<wbr>` 的土法煉鋼。

**「新增文章不需改動程式」：真的驗證過，不是純理論宣稱。** 內容目錄結構是
`content/guides/<locale>/<slug>.mdx`，一個 locale 沒有任何文章時（例如目前的 ja／en）
`getAllGuides()` 誠實回傳空陣列，列表頁顯示「目前尚無指南文章」而非報錯或空白頁——跟票 34
的「誠實空狀態」是同一個模式。寫了一篇真實的 zh-TW 文章（見下）驗證整條管線，而不是只憑
型別檢查通過就宣稱完成。

**真實驗證文章：** `content/guides/zh-TW/getting-started.mdx`——用這個專案自己已經確立的
真實領域知識寫的（CONTEXT.md 的 Blade／Ratchet／Bit 定義、ADR-0007 的合成規則），不是
placeholder 假文——同時也是這條管線第一次端到端真實驗證：標題層級、目錄產生與跳轉、引言／
資料來源用芫荽字體、內部連結（連到 `/combo` 組合建構器）全部截圖與 Playwright 實測確認
正確運作。38 號票（實際內容產出）之後接手真正的內容撰寫工作，這篇只是驗證用的最小範例。

**測試：** `headings.test.ts`（4 個測試，涵蓋標題擷取、忽略非標題的 `#` 開頭句子、
重複標題的 disambiguation 跟 `rehype-slug` 一致、無標題內容回傳空陣列）。

**Pipeline：** `npm run typecheck`、`npm run lint`、`npx vitest run`（180/180）、
`npm run build` 全數通過（含新產出的 1 篇 zh-TW 靜態文章頁 + 3 語言的列表頁）；`next start`
起正式伺服器後截圖驗證文章排版、目錄、空狀態列表，並用 Playwright 實測字體與錨點跳轉。
