# 聯盟網合作對象調查：賽事情境下的食衣住行

調查日期：2026-08-13

## 結論

聯盟網（Affiliates.One）上有適合本站的商家，但**適合的理由不是「本站賣玩具」，而是「本站的使用者這個週末要帶小孩去某個縣市比賽」**。版位應該貼著這條動線做，不要做成泛用電商推薦——那種東西讀者在哪都看得到，放在這裡只會稀釋本站「準」的立場。

四個類別的強弱差距很大，照實說：

| 類別 | 適配度 | 主力候選 |
| --- | --- | --- |
| 行 | 高 | Klook、KKday（租車、票券、停車） |
| 住 | 高 | agoda、Booking.com（跨縣市、東部場次） |
| 食 | 中高 | Uber Eats、家樂福、Pizza Hut |
| 衣 | 低 | Pinkoi（客製周邊／收納），僅此一項站得住 |

**衣是真的弱**，硬湊只會變成填版位。這份調查不幫它補人數。

三件必須先處理的事寫在第 0 節，其中 Vercel 方案那條會直接決定能不能上線。

---

## 0. 上線前的前置條件（先看這節）

### 0.1 Vercel Hobby 方案是非商業限定

你自己的 `TW_veggieprice-/docs/affiliate-setup.md` 已經記下這件事：

> Vercel 免費（Hobby）方案限非商業用途。一旦放聯盟／廣告連結即屬商業使用，請升級到 **Vercel Pro** 或改用允許商用的免費平台（如 Cloudflare Pages）。

本站目前部署在 `old-baby-info.vercel.app`，同樣受這條約束。**在方案問題解決前，`affiliates` 表裡本專案的資料列都不該 `enabled = TRUE`。** 這不是技術問題，是帳號條款問題，程式面做得再乾淨也繞不過。

決定順序應該是：先決定方案 → 再去後台申請商家 → 最後才寫資料列。

### 0.2 受眾主體是兒童，買單的是家長

`data/events.json` 的 767 場賽事，年齡分佈是：

| 年齡類別 | 場次 |
| --- | --- |
| 公開（6歲以上） | 546 |
| 通常（6~12歲） | 205 |
| 成人（12歲以上） | 12 |
| 兒童（6歲~12歲） | 4 |

也就是說，**站上絕大多數賽事的參賽者是小學年齡的孩子**。這件事有兩個後果：

1. 所有檔位的文案都應該寫給家長看，不是寫給孩子看。「幫孩子準備」「賽後帶全家」這種角度，不要用「你一定要買」對著孩子講。
2. 有些聯盟網上確實有、但不該放在這個站的類別，見第 6 節。

### 0.3 這份調查沒有、也不可能有的東西

我無法登入你的聯盟網後台，所以：

- 下面每個商家的「是否確認在聯盟網」欄位，來源是公開資料與你既有的檔位，**不等於你的帳號一定申請得到**。部分計畫需要審核，審核標準各家不同。
- 我**沒有產生任何追蹤連結**，也不該產生。除了 KKday（見 8.1，它用 CID 附加的機制，不需後台產連結），其餘一律要在後台產生帶你專屬追蹤碼的連結。
- 佣金率、Cookie 效期、審核時間都要以後台實際顯示為準。

## 1. 賽事動線：版位要貼的那條線

`data/events.json` 的 767 場（全部 G3）跨 21 個縣市：

| 縣市 | 場次 | | 縣市 | 場次 |
| --- | --- | --- | --- | --- |
| 高雄市 | 173 | | 新竹市／縣 | 46 |
| 新北市 | 140 | | 台南市 | 47 |
| 台北市 | 68 | | 嘉義市 | 20 |
| 桃園市 | 65 | | 宜蘭縣 | 16 |
| 台中市 | 66 | | 苗栗縣 | 12 |
| 其他／未標 | 83 | | 彰化、雲林、屏東、基隆、台東、花蓮 | 各 4–9 |

場地是百貨與玩具店（潤泰南港車站店、遠百信義A13、高雄大立、熊嗨星樂園、陳媽媽玩具、玩具e哥土城……），時間幾乎都是週末 14:00，名額 32–48 人。

推出來的動線是這樣：

```
查賽事 → 決定跑哪一場 → 跨縣市的話要交通/住宿 → 當天到場等待 → 賽後
   ↑                        ↑                      ↑           ↑
 本站                       行                     食          食
```

**版位的價值在於它接在「查完賽事」之後**，這是本站唯一有、別人沒有的上下文。泛用電商連結接不上這條線。

## 2. 行（適配度：高）

跨 21 縣市、週末場次，交通是真需求。但要先講清楚一件事：

> **本站的「其他工具」已經有 Taiwanrail 與 TransitRail，免費查時刻表。** 所以行的聯盟檔位不該是「查交通」，那已經被自家工具滿足了。應該是**那兩個工具做不到的事**：租車、票券、停車。這條界線讓版位誠實——付費連結必須帶來免費工具沒有的東西。

| 商家 | 是否確認在聯盟網 | 為什麼接得上賽事 |
| --- | --- | --- |
| Klook 客路 | 是（[聯盟網官方計畫頁](https://blog.affiliates.one/zh-TW/blog/post/klook-affiliate-program)） | 租車、票券、機場／車站接送。帶小孩加陀螺裝備跑外縣市，租車比大眾運輸實際 |
| KKday | 是（你已持有 CID 25570） | 同上，且**今天就能做**，見 8.1 |

建議的檔位值：

| 欄位 | Klook | KKday |
| --- | --- | --- |
| `id` | `a1-klook-rentcar` | `kkday-rentcar` |
| `partner` | `Klook 客路` | `KKday` |
| `sponsored` | `FALSE` | `FALSE` |
| `priority` | `8` | `7` |

**每個「行」檔位都要查的一件事：適用對象。** Klook／KKday 上的高鐵、台鐵優惠票券有不少是**限外籍旅客**購買的。本站讀者是台灣家長，導過去卻買不了，就是規格 §8 說的「導向與文案不符的頁面」。建立連結前務必在商品頁確認適用對象，不確定就別放高鐵票，改放租車或停車。

## 5. 衣（適配度：低）

**這一類我找不到有說服力的組合，照實說。**

聯盟網上確認有 Nike、CHARLES & KEITH。但戰鬥陀螺不是運動項目，參賽者是坐著打的小學生，「比賽要穿什麼」不是一個真實存在的需求。硬把 Nike 放進賽事版位，讀者一眼就知道是湊數，而這個站的整個資產就是不湊數。

唯一站得住的一項：

| 商家 | 是否確認在聯盟網 | 為什麼勉強接得上 |
| --- | --- | --- |
| Pinkoi | 是（[平台品牌列表](https://blog.affiliates.one/zh-TW/blog/post/s-1291-how-to-make-money-through-affiliate-marketing-in-hk)） | 客製名牌貼紙、陀螺收納袋、選手小物——是周邊不是衣著，但確實貼著賽事 |

建議做法：**先不做衣**。等版位有實際成效數據，再決定要不要用 Pinkoi 補這格。三個檔位的版位比四個中有一個明顯在湊數好。

## 6. 明確不建議的類別

聯盟網上有，但不該出現在這個站：

- **保健食品／美妝**（屈臣氏、日藥本舖、船井生醫等）。跟賽事情境無關，而且面向兒童受眾的站放保健品推廣，觀感與責任都不划算。
- **3C／家電**（Apple、LG、Canon）。純粹是高佣金誘惑，跟動線一點關係都沒有。
- **線上課程**（Hahow）。除非是陀螺／桌遊相關課程，否則同上。

判準很簡單：**這個檔位如果不是因為賺錢，你還會不會放它？** 答案是否的就不要放。

## 7. 後台要逐項確認的事

每個候選商家進資料表前，在聯盟網後台確認這五件事：

- [ ] 計畫是否對你的帳號開放（有些需審核，有些對流量有門檻）
- [ ] 審核要等多久（會影響上線排程）
- [ ] 佣金率與計價方式（CPS／CPA），以及 Cookie 效期
- [ ] 是否有內容限制（部分品牌禁止出現在特定類型網站）
- [ ] **適用對象**——尤其是「行」類的票券商品，是否限外籍旅客

拿到連結後，規格 §8 還要求人工點過一次，確認不是過期頁、且與文案相符。

## 8. 可以今天就做的事

### 8.1 KKday 不需要後台產連結

你的 `affiliate-setup.md` 記載：CID **25570**，機制是在任何 KKday 頁面網址後面加 `?cid=25570`（網址已有 `?` 就改 `&cid=25570`）。

所以「行」的 KKday 檔位不必等審核，現在就能建。做法是到 KKday 挑一個**具體的**租車或票券商品頁，複製網址後接上 CID。

同一份文件也留下一個實測過的教訓，直接適用於本站：

> 避免用 `keyword={crop}` 動態搜尋——部分作物會搜到不相關結果。

本站對應的坑是一樣的：**不要用 `keyword=陀螺` 或 `keyword=` 帶場地縣市去組動態搜尋連結**，KKday 上搜「陀螺」不會有相關商品，搜縣市則會搜出一堆與賽事無關的行程。固定指向一個你人工確認過的商品頁或分類頁，比動態搜尋穩。

### 8.2 建議的上線順序

1. 先解決 Vercel 方案（第 0.1 節）——這之前不要 `enabled = TRUE`。
2. 用 `scripts/sql/affiliates-seed.sql` 第 1 節的煙霧測試，確認整條線通。
3. 第一個真實檔位做 **Uber Eats**（已有連結、風險最低）。
4. 收 1–2 週 `audit_log` 的曝光與點擊，再決定要不要加第二個。

一次只加一個檔位，成效數據才歸得了因。三個檔位同時上線，之後看到的 CTR 分不出是哪個帶來的。
