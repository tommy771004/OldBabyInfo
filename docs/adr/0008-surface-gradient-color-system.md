# 色彩系統：一組連續色階，兩端各自的安全區，中段禁放文字

落實 ADR-0006 的「連續過渡」約束（05 號票）。全站用一組 11 階的暖色調（近黑的暖褐 → 赤鏽 → 暖陶土白）連續色階，深端對應「場上」、淺端對應「場邊」，不是兩組配色。刻意不用冷藍炭黑（常見的深色版預設）、也不用米白／燕麥（常見的淺色版預設）。

## 色階與角色

- `--surface-950` 到 `--surface-50`：11 階連續色階，數值兩端分別是場上背景與場邊背景。
- `--ink-on-dark` / `--ink-on-light`：直接取色階的兩個極值端點，不另外調色。
- `--accent-on-dark` / `--accent-on-light`：同一色相家族，但拆成兩個深淺變體——單一強調色無法同時通過深色與淺色背景的 AA 對比，這不是取巧，是連續色階系統下本來就該有的答案：強調色不是固定色碼，是色階上依所在位置取用的一個角色。
- 主背景維持暖黑與深鐵色，閱讀面由同一色階推導成陶土淺色；微電流使用低飽和銅白，不增加另一套霓虹色系。
- 每支 Part 的真實代表色只用在該 Part 的剪影、軌跡或數值變化，不擴散成整頁主題色。
- 不使用藍紫漸層、霓虹 glow 或彩色粒子。

所有數值都用真正的 WCAG 相對亮度公式算過，不是憑感覺選色碼。

## 意外發現：漸層中段是文字禁區

用 Playwright 實際截圖＋逐點量測漸層內插後的真實對比度（不是只查最近的命名色階）才發現：色階中段大約 **50%–60% 的範圍**是中等亮度的褐色，深色墨（白字）與淺色墨（黑字）在這個範圍雙雙掉到 WCAG AA 門檻以下（最低到 1.03，幾乎不可讀）。這是背景亮度落在中段時的物理限制，不是調色能解決的問題。

**結論：背景可以連續漸變，但可讀內容不能疊在漸層的正中段。** 深色墨安全區約在色階 0%–45%，淺色墨安全區約在 62%–100%，中間留一段刻意的無文字過渡帶。示範頁（`/color-demo`）用這個規則排版，實測截圖確認每一段文字都清楚可讀。

## Consequences

- 07 號票（競技場 SVG signature）與 39/40 號票（首頁 composition）疊加內容到這個漸層背景上時，必須避開色階中段，或在該區段額外加不透明度襯底——不能假設「漸層本身連續」就等於「疊在上面的文字到處都能讀」。
- `/color-demo` 頁面本身是這個限制的活文件，之後色階數值若調整，重新截圖驗證，不要只看程式碼綠燈就當作過關——這類問題是視覺／量測層級的 bug，typecheck 與 build 都不會抓到。
