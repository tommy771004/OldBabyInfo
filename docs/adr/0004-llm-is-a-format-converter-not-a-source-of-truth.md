# 語言模型只做格式轉換，不作為事實來源

抓取管線使用 OpenRouter 上的免費模型，而這類模型的失敗方式不是報錯，是回傳格式正確、看起來合理的錯誤數字——JSON 修復與 schema 驗證都攔不住，因為它們只驗格式不驗真假。而一個查詢站給出錯的數值，比查不到更糟。因此語言模型只在「輸入是人寫給人看的散文或半結構化表格」時出場，且受四條規則約束。

## 規則

1. 有結構化來源（JSON 檔、商店 API）時禁用語言模型，一律以決定性解析取得。
2. 每個由模型抽取的欄位必須附帶 Source Excerpt 與來源連結，否則管線拒收。
3. 同一段輸入交給兩個不同家族的免費模型，結果一致才自動送出；不一致標記為 Needs Review。
4. 除 schema 之外必須有值域驗證（數值範圍、日期合理性、價格為正）。

## Consequences

- 慢變動且要求準確的資料（Part、Event、Mold Batch）由排程任務寫入 repo JSON 並自動開 PR，經人工核可後才發布；人工做的是核可，不是打字。
- 快變動且容錯高的 Stock Listing 直接寫入資料庫並標註抓取時間，不佔用人工時間。
- 抓取失敗時保留舊值並顯示資料時間，絕不顯示空白或零。
